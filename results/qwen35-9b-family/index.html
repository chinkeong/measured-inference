Ornith-1.5-9B against Qwen3.5-9B on one RTX 3090

1. What is being compared

Qwen3.5-9B is the base model and the fixed reference point. Ornith-1.5-9B was built from it by further training. Both are 9.11 GiB in the same 8-bit format with 33 layers, a context length of 262,144 tokens, the same attention head counts, and the same memory cost per token. Because the shape is identical, anything that differs between them comes from the training, not the design.

Every number on this page was measured on one RTX 3090 with 24 GB of memory, running Ubuntu. Most measurements were taken with both models running in one alternating session.

Why one session matters. This rig produces two throughput levels about 13 % apart, and nothing recorded predicts which one a run lands on. Seven candidate causes were tested and eliminated. Numbers taken on different days are therefore not comparable as absolutes, so the two models were alternated inside a single sweep, first probe of each load discarded for clock ramp, and the reference model's own absolute is published so a later sweep can form ratios against it.

The file choice was the first trap. Third-party GGUF conversions of this architecture silently drop the multi-token-prediction layer — 243,290,624 parameters — leaving a 32-layer model. The file size gives it away: 9.79 GB with the layer, 9.53 GB without. Both arms here are plain Q8_0 from conversions that keep it, verified at the GGUF header at block_count 33. Pairing a 32-layer file against a 33-layer one would have published a packaging difference as a model difference.

2. The recommendation

Use Ornith-1.5-9B for text work. Both models produce text at the same speed — 84.17 and 83.80 tokens per second, a 0.5 percent difference. What separates them is finishing: on the same 175 test questions, Ornith finished in 4,231 seconds, 41 percent of the 10,235 seconds Qwen3.5-9B took.

The reason is not speed. Qwen3.5-9B often does not stop writing. It ran past the answer limit on 23 of 175 questions; Ornith did so on 9. A cut-off answer scores zero, so the extra time produces nothing.

Ornith scored 68.9 out of 100 on the shared test set against Qwen3.5-9B's 61.6. That 7.3 point difference is a lean, not a verdict — each test used only 25 questions, too few to settle small differences. The stopping behaviour is the large and consistent finding. If you need image or video input, use Qwen3.5-9B; Ornith was measured only for text here.

3. Plain words

Token
A piece of a word. Models read and write in tokens, not letters.
Tokens per second
How fast text comes out. 84 is faster than a person reads.
Context length
How much text the model can hold at once. Here, 262,144 tokens.
Quantisation
Storing the model's numbers with fewer bits so the file is smaller. Both files here are 8-bit.
Answer limit
The maximum length an answer may reach before it is cut off. Here, 16,384 tokens.
Truncated
An answer that hit that limit and was cut off. It is scored zero.
Greedy
The simplest setting: always take the most likely next word.
Chat template
The wrapper that turns your question into the exact text the model sees.

5. Speed

Both models produce about 84 tokens per second, faster than a person reads. Qwen3.5-9B measured 84.17 tokens per second against Ornith-1.5-9B's 83.80, a ratio of 0.9956. They alternated in one session, so a slow moment could not be mistaken for a property of one model. With recommended settings, which include a repetition penalty, Qwen3.5-9B measured 78.52 tokens per second and Ornith measured 78.77, a ratio of 1.0032. Those settings cost about 0.70 milliseconds per token — the sampling work, not the model.

Both models repeated themselves under the simplest setting, which always takes the most likely next word. That repetition comes from the shared base model; neither model's training introduced it.

The sampler costs a fixed time per token, not a fraction. Converting the greedy/recommended gap to time per token gives 0.765, 0.703 and 0.635 ms across three separate quantisations of the same model. A near-constant offset is the signature of fixed per-token sampling work — top-k 20 plus top-p plus a presence penalty over a 248,320-entry vocabulary — and not of anything the model is doing differently. The percentage looks larger on faster files only because the base per-token time is smaller. The 20 % drift across the three means consistent with, not proved.

Repetition is inherited. The Ornith field guide recorded LOOP on every greedy probe and treated it as a property of that model. The reference model does the same thing on the same prompt at the same sampler. That claim could not be made while the reference existed only as a citation.

6. Quality

Ornith scored higher than Qwen3.5-9B on average across five tests: 68.9 out of 100 against 61.6. Both models answered the same 175 questions, on the same seven test sets, with the same settings, on the same machine.

Ornith led on school maths (100.0 to 92.0 on GSM8K), harder maths (60.0 to 48.0 on MATH-500), code completion (72.0 to 56.0 on MBPP), and summarising (24.3 to 20.0 on MeetingBank). Qwen won one test, HumanEval code writing, with 92.0 against 88.0. Each test used only 25 questions, so a difference of about 10 points can appear from chance alone. Single tests are suggestive, not settled.

The clearest difference was how often each model ran past the answer limit: 23 times for Qwen, 9 for Ornith. Two further tests were scored by three independent judges. Ornith scored 67.6 and 79.9, Qwen 61.3 and 75.0. Six of Qwen's fifty judged answers were empty because they exceeded the limit, against one of Ornith's.

A large part of the judged gap is not writing quality. An empty answer is rated 1 by unanimous seats. Six of Qwen's fifty judged answers were empty at the cap against one of Ornith's, so the 6.3 and 4.9 point gaps are substantially the same stopping failure the scored sets show, arriving through a different instrument.

7. Where the two models are the same

The two models are identical in every structural dimension: 33 layers, embedding width 4096, 16 attention heads, 4 key-value heads, head size 256, context length 262,144 tokens, and the same memory cost per token. Any measurement of memory use or speed applies to both without repeating it. If you have sized a machine for one, that holds for the other.

The one full-size setup measured — the 8-bit file at the full 262,144-token context, with image support and draft model loaded — used 20,336 megabytes of a 24,122-megabyte budget, leaving 3,786 megabytes spare. That figure holds for both. The chat templates differ in text but produced identical input for all 175 test questions, because those questions carry no system message.

Measured KV slope: 33,792 bytes per token, against 32,768 implied by the header — 3.1 % higher, and the measured figure is the one to size with. The projector costs 1,130 MiB and the draft head 2,266 MiB, additive at 3,396 MiB.

The templates differ but do not act. Ornith's is 7,756 characters (a4aee8af…), the reference model's 7,992 (8452ca85…). The only substantive difference is a 39-line system-message merging block. Rendering all 175 suite prompts through both gives 175 identical, 0 different — every rule-21 prompt is a bare single user turn.

9. What this comparison cannot say

No single test is large enough to declare a winner. Each test used 25 questions, and about 10 points of difference can come from chance at that size.

The comparison cannot explain why Qwen3.5-9B fails to stop generating. Swapping the two models' chat templates changed nothing, because both templates produce identical input for these questions. Training is the only remaining explanation, by elimination, not proof. It says nothing about tasks that use system instructions or tools, where the two templates genuinely differ. An agent harness is exactly that case.

Image handling was measured only for Ornith, so there is nothing to compare. Speculative decoding was not compared: Ornith ships an extra small model for it and Qwen3.5-9B does not. The judged scores were produced by a Claude model, and this page was written with Claude. The spread between the three judges is published beside every judged number for that reason.

The crossover had no statistical power and the control says why. The 2×2 returned four bit-identical cells — Qwen weights 13/8 truncations under either template, Ornith weights 3/5 under either. That is not evidence that weights cause the difference; it is a restatement of the render control, which found the two templates emit the same bytes for all 175 prompts. The experiment could not have detected a template effect under any outcome. What it does establish is that the confound is eliminated for this suite: the 23-vs-9 gap cannot be a template artefact, because there is no template difference here to be an artefact of.

Cost recorded honestly: two GPU hours bought a result a three-second render comparison would have predicted, and predicted better, because the control also bounds where the conclusion stops applying.

Two Bits, Same Answer

Two quantisations of Qwen3.8-27B — 4-bit and 2-bit — run against the same 225 agentic coding tasks on the same card, from byte-identical inputs. Their scores are indistinguishable. The smaller file spends about a third more energy — the one difference here that is statistically resolved.

This page reports how the two files differ from each other. It is not a score for the model, and no comparable published score exists — aider's polyglot leaderboard has not been updated since ten months before this model was released. See what these numbers are not.

Two files of the same model, differing only in how tightly the weights are packed. The smaller one frees 4.4 GB of video memory — the difference between fitting on a card and not. The question a buyer actually has is what that costs.

01 — The comparisonSame accuracy, more of everything else

Each exercise is attempted twice, and the mechanism lives there. The model writes a solution, the harness runs that exercise's own unit tests, and if they fail the model is shown the failure output and asked to fix its own mistake. The pass rate the two files tie on is the state after that second attempt.

Most passes here are repairs rather than first drafts: 69% and 80% respectively of all passes arrived only on the second attempt. That is what makes the rest of these numbers legible. The 2-bit file lands a clean first answer far less often — 8.4% against 13.3% — and then recovers to exactly the same second-attempt rate by leaning harder on the repair step. It is not less capable at these tasks so much as less likely to land them cleanly, and every extra repair is a second full generation: the problem read again, a fresh solution written, a test failure explained. That is what the overheads below are made of — extra work, not slower work.

The equal totals sit on top of a lot of disagreement. Of 225 exercises, 66 were solved by both arms, 99 by neither, and 60 by exactly one — split almost evenly at 30 and 30. The matching totals are therefore substantially coincidence. The pass rates are indistinguishable, which is not the same as equal: the interval spans thirteen points, and a real difference anywhere inside it fits this data.

What that disagreement is NOT known to be. It is tempting to read 60 discordant exercises as "the two files succeed at different things", and this page said exactly that in an earlier draft. It is not supported. Nothing here separates a difference caused by the quantisation from ordinary run-to-run variation, because this benchmark has never been run twice with the same file on this rig — there is no test-retest baseline.

Two measured facts say the baseline would not be zero. First, the repair loop above: when most passes arrive only on the second attempt, an exercise turns on whether one particular failure happened to be recoverable — the regime in which a small perturbation flips an outcome most easily. Second, this campaign has already measured that decoding here is not bit-reproducible run to run even at temperature 0, because a change in batch shape flips near-ties. The discordance is therefore an upper bound on what quantisation explains, not a measurement of it.

What is resolved is the cost. Its confidence interval excludes 1.0, so unlike the accuracy difference the energy difference is a measured result rather than a null. How large the token overhead looks depends on what it is divided by: 20% more as a paired median over the 66 exercises both arms solved, 41% more in total across all 225, and 55% more per exercise actually solved. Wall time tracks it — 20% paired, 36% on seconds per case — and energy runs roughly a third higher per task actually completed.

Per token, the smaller file is the more efficient one. It decodes at 77 tok/s against 70, and costs 6.66 J per completion token against 6.92 — about 4% better. It then needs 20% more tokens, which more than cancels the gain. Efficiency reverses depending on whether the denominator is a token or a finished task, and only the second one is what a user pays.

Speculative decoding moves this workload off the memory roofline and onto the power limit, and it is the single largest lever measured anywhere in the campaign.

Drafter off, the same file runs 45.2 tok/s — 644 GB/s, or 69% of the roof, which is bandwidth-bound. Turn the draft head on and measured throughput exceeds the one-weight-pass-per-token ceiling of 65.7 tok/s, so that model cannot explain it: real traffic is 398 GB/s and the memory system has 57% of its capacity spare. What binds instead is the 350 W board limit, active on essentially every busy sample.

The cap is paid in core clock, not memory clock

Reading both clocks against their own maxima explains why the bandwidth roof stays put while achievable throughput falls short of it: the SM clock is held at 1650 of 2130 MHz (77%) while the memory clock sits at 9501 of 9751 MHz (97%). The power limit lowers the compute roof and leaves the bandwidth roof untouched. Power is being spent holding a clock this workload is not using — an unexploited firmware lever, and one this rig cannot test, because llama.cpp cannot express a clock policy and the driver does not expose one.

Cooling is not the constraint, but there is no headroom either. Thermal limiting fires on 3% of busy samples while the fan runs at 100% and the die sits at 83 °C median. A better cooler buys perhaps 3%; the current operating point already costs the entire fan curve. Memory junction temperature is not exposed by NVML on this part and is absent for that reason, not by omission.

04 — RetractionsClaims this campaign published and then killed

Dead claims are kept as dated case studies rather than deleted. Each of these was measured, published, and then refuted by a better measurement — in every case one this campaign ran against its own work.

Corrected — the settings were blamed without checking

Four deliberate choices — reasoning off, the whole edit format, quantisation and a 32k context — all depress the absolute score, so it is not comparable with published leaderboards.

Checked against aider's own published data, three of the four go the other way or do nothing. whole beat diff on every published Qwen3 matched pair by 2.2 to 4.5 points and is aider's own default for lesser-known models. For Qwen, aider recommends thinking off and its no-think arm scored 11.5 points higher than its thinking arm. The 32k window shows no evidence of harm — the largest file the model re-emits is about 1,900 tokens, and 100% well-formed is the signature of a window that is not truncating. Only quantisation clearly costs. The conclusion that the score is not externally comparable survives, but for a different and simpler reason: no comparable published score exists at all.

Withdrawn — discordance attributed without evidence

The two files succeed on materially different tasks: 60 of 225 exercises went to exactly one of them.

The count is right; the attribution is not. Nothing measured here separates a quantisation effect from run-to-run variation, because 69% and 80% respectively of passes arrive only on a second attempt, and decoding here is already known not to be bit-reproducible run to run. The baseline flip rate has now been measured (2026-08-27, UD-IQ4_XS, aider polyglot benchmark, whole edit format, reasoning off, -c 32768, n-max 4 / p-min 0.75, greedy, 113 exercises paired by case and language): both runs scored 43.4%, identical, while 18 of 113 exercises flipped verdict — a flip rate of 15.9% (95% interval 10.3–23.8), split exactly 9 pass→fail and 9 fail→pass. This page predicted the flip rate was “certainly above zero” because greedy decoding reproduces byte-for-byte only when the batch is shaped identically, which an agentic run does not do. That prediction is now confirmed: a sixth of the individual verdicts moved underneath a pass rate that did not move at all. At that noise floor, comparing one run of each file across 225 exercises would produce roughly 36 disagreements (interval 23–54) even if the files were identical in capability. The observed cross-file count is 60 of 225 = 26.7% (95% interval 21.3–32.8). Whether the gap above that floor is real depends on which file’s noise it is tested against — a p-value (the probability of seeing a gap this wide from noise alone) below 0.05 is the conventional line for “probably real.” Against the 4-bit file’s floor of 15.9% the gap clears the line (z = 2.21, p = 0.027), but that was the quieter of the two files. Against the 2-bit file’s noisier floor of 22.1% (25 of 113, 95% interval 15.5–30.6, measured 2026-08-28), the same 60 is easily explained by chance (z = 0.91, p = 0.364). Pooling both retests — 43 flips out of the 226 exercises both retests covered, a combined floor of 19.0% (interval 14.4–24.6) — gives z = 1.93, p = 0.053, which does not clear the line either. No quantisation effect is demonstrated. 60 discordant exercises remains an upper bound on what quantisation explains, and most of it — possibly all of it — is the benchmark talking to itself.

Open mechanism. Aider shuffles its exercise list unseeded, so the order differs between runs, and the server’s KV cache carries state across requests — different cache-reuse paths give different numerics. Nothing here isolates which factor dominates.

Limitations on the retest itself. Run 1 was launched by hand and without --metrics; the retest used the script and has it. --metrics only exposes a Prometheus endpoint and does not touch sampling, the cache or generation, so it cannot flip an exercise, but run 1’s server flags were never recorded anywhere — its configuration is known from the recipe rather than from a log of that run. The retest drew a random 113 of the 225 (aider shuffles unseeded before truncating), so it is an unbiased subsample, not a prefix, and pairing is by name. Projecting its rate onto 225 is a projection.

Corrected — a true number that read as the wrong claim

A 2-bit quantisation solved the same number of coding tasks as a 4-bit one.

True as arithmetic, misleading as a claim. Both finished 96 of 225 — but only 66 were solved by both, and 59 by exactly one, split 29 to 30. The equal totals conceal disagreement on a quarter of the benchmark, and the sentence invited the reading that the two files are interchangeable here. They score alike in aggregate; they do not succeed on the same work.

Corrected — energy compared across different exercises

The 2-bit file costs 1.52× the energy per solved task: 23.2 kJ against 15.3 kJ.

Paired properly: 1.32×. The first arm's power sampler was started after its benchmark, so it has telemetry for 132 of 225 exercises while the second has 222. The cost table averaged each arm over whatever it happened to have — different exercises — and divided tokens over a third set again. Recomputed over only the exercises where both arms have power, the ratio is 1.376× on total energy, 1.239× as a per-exercise median, and 1.319× per solved task. The direction survived; the magnitude was overstated by about 15%.

Retracted — drafter depth

Acceptance sits at 89% of the configured cap and stays 59% at the last permitted position, so the flag and not the draft head limits speculation; raising it should be worth about +24%.

Measured: −0.8% at n-max 6, +2.0% at n-max 8. Mean accepted length rose exactly as predicted, 2.71 → 3.54, and throughput did not follow. The cost model assumed a constant marginal cost per speculated token; deeper drafts cost more per token and are accepted less often — 99/73/55/44%, decaying to 13% by position 7 — so wasted work grows faster than accepted work. A boundary acceptance rate says nothing about the marginal return of the next position.

Retracted — energy spread

Energy per completion token varies 30× across exercises.

Measured correctly: 3.2×. The window was anchored to the results-file timestamp minus the recorded duration — but that duration covers only model calls, while the file is written after the unit tests and the build cleanup. Right length, wrong place: it billed test-time idle to the model. The cheapest exercise was published at 0.417 J/token against a true 5.830.

Retracted — polling bias

A poll-derived phase split overstates the long phase by 6.3 points.

Measured over the full arm: −1.5 points — wrong in magnitude and in sign. The earlier figure came from a four-minute window dominated by start-up transients. Splits already published stand. The lesson kept is that a bias estimated on a short window is not a small version of the long-window bias, and may not even point the same way.

Retracted — thermal headroom

Thermal throttling never fires on this part.

It fires on 3.0% of busy samples. The earlier reading counted idle samples, which are 14% of the trace and swamped the histogram. Idle is a state, not a limit.

Corrected — uncertainty understated

With 59 discordant pairs, a difference of up to 1.3 points remains consistent.

The true interval is about five times wider. The rule of three is the bound for zero discordant pairs and is the wrong instrument once there are any. The paired comparison at the top of this page now carries a proper confidence interval. Understating uncertainty is the one direction this campaign must never round.

05 — ComparabilityWhat these numbers are not

The pass rates here are internally comparable and externally not — but not for the reason first assumed. An earlier draft of this section claimed four deliberate choices had depressed the score. Checked against aider's own published data, three of the four go the other way or do nothing.

Why no clean comparison exists, and cannot

Aider's polyglot leaderboard data file has not been updated since 4 October 2025. Qwen3.8-27B was released on 14 August 2026 — about ten months later. There is no leaderboard entry for this model, and there structurally cannot be one. No aider polyglot score for it exists anywhere: not on the board, not in aider's blog, not on the model card.

Two further gaps make any cross-comparison unsafe, and both are absences rather than differences. All 69 leaderboard entries were served by hosted APIs; none was served locally. And the leaderboard records no precision field at all — so it cannot be said that its open-weight entries are full precision, only that their precision is unknown. Aider has itself documented that provider-served open weights arrive at provider-chosen quantisation.

One number on this page that should not be read as quality. The 100% well-formed rate is close to automatic under whole: aider writes any unlabelled fenced block straight over the solution file and does not count that as malformed. Two leaderboard models with 100% well-formed scored 3.6% and 4.9% on the actual task. It means the harness could parse the output. It says nothing about the code.

What remains true is the narrow claim this page makes: two files, one benchmark, one machine, identical settings, byte-identical inputs. The comparison between them is sound. Its absolute level is a measurement of a configuration, not of a model.

06 — LimitsWhat this rig cannot say

Stated plainly so absence is never read as a result.

  • No full-precision anchor. The quantisation ladder is referenced to UD-IQ4_XS — itself a lossy 4-bit file — because 55 GB of BF16 does not fit a 24 GB card, and 29 GB of Q8_0 would put roughly 7 GB of weights on a CPU with 31.8 GB of system RAM. Borrowing Quesma's published BF16 point bounds the anchor at at least 1.1% of tokens away from full precision — a lower bound, which cannot prove it is close.
  • Wall power is not measured. Every watt on this page is the NVML GPU board domain. Power supply, CPU, memory, drives and display are excluded.
  • Reasoning is off throughout. Other people's work finds the gap between quantisations widens at higher reasoning effort, so this is one corner of that surface. A full sweep is four more arms and fourteen hours of exclusive machine time.
  • Test-retest baseline now measured. Both arms have been repeated with their own weights (UD-IQ4_XS 2026-08-27, UD-Q2_K_XL 2026-08-28; whole edit format, reasoning off, -c 32768, n-max 4 / p-min 0.75, greedy, 113 exercises paired by case and language). The 4-bit file flipped 18 of 113 = 15.9% (95% interval 10.3–23.8), the 2-bit file flipped 25 of 113 = 22.1% (95% interval 15.5–30.6). The cross-file disagreement of 60 out of 225 (26.7%) does not clear the noise floor on two of three tests (p = 0.364 against the 2-bit floor, p = 0.053 pooled), so no quantisation effect is demonstrated. Every statement about which exercises differ is still bounded by that noise, and most of the 60 is consistent with the benchmark talking to itself.
  • One machine, one runtime, one context length. No second GPU vendor, no second inference engine, and 32k rather than the ~98k an agentic benchmark can demand.
  • Per-process GPU attribution is impossible here. nvidia-smi pmon reports nothing per process under Windows WDDM, so the server's share cannot be separated from the desktop's.

The practical read. If 4.4 GB of video memory is what stands between the model fitting and not fitting, the 2-bit file costs about a fifth more tokens and roughly a third more energy per finished task, at a pass rate this sample cannot distinguish. If the 4-bit file already fits, there is no measured reason to move down.

The verdict. The 2-bit file works, and it reaches the same second-attempt score. It is the less stable of the two in the one way this run can show — fewer answers land on the first try, and more of the score is bought back through the repair loop — and it charges more tokens, more wall time and more energy for the same finished work. Take it when the 4.4 GB is what makes the model fit at all; otherwise the 4-bit file is the better choice.

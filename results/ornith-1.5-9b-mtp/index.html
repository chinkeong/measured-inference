1. What this page is

This page reports measured settings for Ornith-1.5-9B, a 9-billion-parameter text and image model, on one NVIDIA RTX 3090 graphics card with 24 gigabytes of memory, running Ubuntu with the desktop active. Every number was recorded on that machine, not estimated. The page covers which file to download, how much memory each setup needs, how fast the model runs, how much electricity it uses, and what it does with images.

2. Plain words

Token
A piece of a word. Models read and write in tokens.
Quantisation
Storing the model's numbers with fewer bits so the file is smaller. 8-bit, 4-bit and 2-bit files are measured here.
Context
How much text the model holds at once. This model's maximum is 262,144 tokens.
KV cache
Memory the model uses to remember the conversation so far. It grows with the context.
Speculative decoding
A small helper model guesses the next few tokens and the big model checks them. Faster when the guesses are good.
Truncated
An answer that hit the length limit and was cut off. It is scored zero.
Greedy
The simplest setting: always take the most likely next token.

3. The recipes

For the best quality, load the 8-bit file with all layers on the graphics card, the full 262,144-token context, and image support. Turn speculative decoding off. This produces 78.60 tokens per second, faster than a person reads. It uses 20,336 megabytes of a 24,122-megabyte budget with image support and the small helper model loaded, leaving 3,786 megabytes free.

The 8-bit file is the right choice because it stays close to the original unshrunk model, disagreeing on only 2.4 percent of words. The 4-bit file disagrees on 14.1 percent, and the 2-bit file on 24.0 percent. Smaller files run faster but they produce different answers.

If speed matters more, the 4-bit file with speculative decoding on reaches 148.03 tokens per second, 1.238 times faster than without it. But speculative decoding changes the answer. You do not get the same answer faster; you get a different answer. This was confirmed by running the same question twice with the setting on and twice with it off. The repeats matched exactly, so the difference is the setting, not chance.

Acceptance is the speedup; mean draft length is the throughput predictor. R2 accepts 0.902 of drafted tokens. More drafting is not more speed: at draft length 10 with no probability floor, acceptance falls to 0.298 and throughput drops to 115.64 tokens per second — slower than no speculation at all, at 0.967 × the baseline.

Why R1 turns speculation off, in full. Speculative decoding is supposed to be free: a small draft model proposes the next few tokens, the big model verifies them, and rejected guesses are resampled from the big model's own distribution, so the text that comes out is identical to not using it. That is the entire reason to use it.

On this model it is not identical. Same prompt, same seed, temperature 0:

speculation OFF   sha256 26feb103…   16,407 chars   4,096 tokens   finish=length
speculation ON    sha256 363a2a00…    4,100 chars   1,135 tokens   finish=stop

Each setting reproduces itself exactly — both repeats of each configuration are bit-identical — so this is not sampling noise, it is the flag. The practical consequences are that a benchmark taken with speculation off does not describe a deployment with it on; that any comparison where one arm uses it is confounded; and that the flag belongs in your recorded configuration beside temperature and seed, not beside thread count.

In this particular sample the speculative run was the better one — it finished the task in 1,135 tokens and stopped cleanly, while the non-speculative run ran to the 4,096-token cap without finishing. That is one sample. Different is measured; better is not, and is not claimed. The mechanism is also unknown: the draft path or the extra head's interaction with sampling are candidates, neither established.

4. Which file to download

The 8-bit file is the closest to the original model. Over 294,912 words of text, it picks the same next word 97.6 percent of the time. The 4-bit file agrees 85.9 percent of the time and the 2-bit file 76.0 percent. The files are 9.11, 5.38 and 3.60 gigabytes respectively.

A common ranking method called perplexity put them in the opposite order, scoring the 4-bit file best and the 8-bit file worst. That ranking is wrong here. The 4-bit file scored better than the original model it was made from, which is not possible for a copy. A shrunk file cannot know more than its source. Perplexity measures how confident a model sounds, not how close it stays to the original.

If the answer matters, use the 8-bit file. If speed matters more than exactness, the 4-bit file is a real trade and not a free one.

The perplexity inversion, stated precisely. Q4_K_M scores 7.9544 against the BF16 original's 9.0355 — 1.08 better than the weights it was made from. A quantisation cannot beat its source. Low perplexity here is a differently-shaped distribution, not a better model. Ranking this ladder by perplexity would have crowned Q4_K_M and screened out Q8_0 at the first gate.

The fidelity knee is BRACKETED, not resolved — it lies between 3.36 and 5.03 bits per weight on this ladder. The rungs measured are too far apart to place it more tightly, and that is reported as a bracket rather than interpolated to a false precision.

Format is not the axis; bits per weight is. Two files of the same model at the same size — Q2_K at 3.4196 bits per weight and an adaptive IQ mix at 3.4272 — were measured in one sweep. The codebook file was faster (134.75 against 125.10 tokens per second) and did less compute per unit time (SM 14.22 % against 15.95 %). Both signs are opposite to the "codebooks cost throughput" story, which is retired. At that size the adaptive mix also held 80.7 % top-token agreement against Q2_K's 41.1 %, on a larger file.

6. Electricity

Every number here was measured from the graphics card itself, with the card's idle draw of 31.12 watts subtracted. What remains is the cost of the work, not the cost of the machine being switched on. Producing one word costs 3.454 joules at 8-bit precision, 2.424 joules at 4-bit, and 2.186 joules at 2-bit. The saving is smaller than the file size suggests: the 2-bit quantisation is 39.5 percent the size of the 8-bit one but uses 63.3 percent of the energy.

A 198-question science exam cost 2,029 watt-hours and produced 142 correct answers, which is 14.29 watt-hours per correct answer. About 441 of those watt-hours produced nothing at all, because those answers ran past the length limit and were scored zero.

Two independent instruments agree on the shape. Cutting the file to 0.395 × the bytes buys only 0.633 × the energy per token, and joules-per-token-per-gigabyte rises at every step: 0.379 → 0.451 → 0.607. That is the same curve as the bandwidth-efficiency constant falling 0.82 → 0.73 → 0.54 across the same three files, measured on a different day by a different method. The agreement is about the effect; the mechanism remains open after the matched-size pair above retired the codebook explanation.

Cross-check on Q8_0. Three windows, three workloads: 3.266, 3.493 and 3.454 J/token. Nothing here rests on one window. The first is an upper bound — coarse windows do not separate prefill from decode.

7. Images

The model does not pretend to see. When a question mentioned an image but none was attached, it said it saw nothing and asked for one. Asked whether a red triangle appeared in a picture containing a black circle, it said no and named the circle.

It misreads small text confidently. A test image contained a six-digit number at several sizes. At 1,536 by 864 pixels and below, it got the number wrong every time in three tries at each size. At 1,600 by 900 pixels and above, it got the number right every time. When wrong it never said so. It returned the same wrong answer all three times, so running it twice produces agreement that looks like confirmation but is not.

Send screenshots at 1,600 by 900 pixels or wider. An image costs about 1,010 pixels per token up to about 2 million pixels. Above that the image is shrunk, so a 4K screenshot costs the same as a 2K one with half the detail per token.

The threshold is sharp and it is not a pixel count. 1,280 × 1,280 carries 1,638,400 pixels and 1,609 image tokens — more of both than 1,600 × 900 — and fails every repeat. Any explanation must account for that inversion. The patch grid (patch 16, merge 2, canonical image size 768) and how a given aspect ratio is resized onto it are the obvious suspects, and they are recorded here as suspects, not findings.

The rendering critique loop works and discriminates. Two pages were rendered and screenshotted, one correct and one deliberately broken with overlapping text and an image that fails to load. The model named both real defects on the broken page and did not report them on the good one.

A consumer-side warning. The visible reply field came back empty on most vision replies, with the whole answer in the reasoning channel. Any client that reads only the standard content field will see nothing at all.

8. Benchmarks, and how much to trust them

On a standard seven-test suite this model scored 68.9 out of 100 across the five tests that can be scored automatically. On a 198-question graduate science exam it scored 71.7 out of 100, against a published figure of 86.4. The gap is almost entirely one thing: 43 of the 198 answers ran past the length limit and were scored zero.

Among the 155 questions it did finish, it answered 142 correctly, which is 91.6 percent. Both numbers are true and neither should be quoted alone.

A finding about the instrument, not the model. This model emitted zero bare-letter answers: it always writes "Answer: X" after prose. Under the definition model cards use when quoting a "format compliance" percentage — the reply is a single letter — it scores 0 %. Under this harness's extractor it is 100 % parseable. Same 198 generations, two defensible readings, 0 against 100. Any published compliance percentage is a property of the grader's definition at least as much as of the model.

Sample size. The seven-test suite uses 25 questions per set. At that size roughly 10 points of difference can arise from chance alone, so a single set's score is suggestive and the composite is the better-powered figure. Categorical findings — a model truncates, or it does not — survive small n; point differences do not.
